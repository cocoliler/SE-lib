# 功能需求规格

| 编号 | 需求 | 首版验收 |
|---|---|---|
| R01 | 结构化规格 | 表单保存名称、描述、业务目标、输入、输出、约束、完成条件、验收标准、优先级。编辑用 revision 比较，后端返回字段错误 |
| R02 | 自动分解 | Planner 读取固定规格修订，产出 Schema 合法、角色可分配、可拓扑排序的候选 |
| R03 | 图上审查 | 查看与编辑任务、依赖、角色、输入、成果与标准，修改使旧批准失效 |
| R04 | 执行协作 | 用户确认 revision/hash 后运行，独立专业 Agent 有真实上下游数据传递，至少一次并行汇聚 |
| R05 | 执行观察与控制 | 可查看角色、状态、实际输入输出、耗时、错误、通信与工具记录。运行可取消，人工节点可批准或拒绝 |
| R06 | 结果验证 | 程序检查可自动验证项，Reviewer 关联缺陷与证据，可人工批准一次修订与复审 |
| R07 | 持久化 | 重启可读规格、计划、运行快照、审批、事件和成果，未完成记录说明中断 |
| R08 | 可复现 | TEST 与 REAL 分别执行学生选课案例，记录命令、结构化证据与人工判定 |

输入表单将目标与描述分开，输入和输出以列表编辑，验收项有稳定 ID，完成条件包含可以验证的要求。Planner 与 Reviewer 使用同一规格修订。技术约束为 Windows 本地、外部依赖限模型服务、模型 Key 不进入前端。优先级见[首版范围](MVP_SCOPE.md)。

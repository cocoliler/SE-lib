# 开发路线图

首版先串行联调，再补齐正式验收。阶段出口须有可复现测试证据。编号衔接既有分工，但以本次的任务边界为准。

| 阶段与目标 | 任务 / 负责人 | 前置 | 验收与测试 | 风险 |
|---|---|---|---|---|
| Phase 0 审计和研究 | T01 A/F：核对 main、原型及参考项目 | 无 | 差异表能定位文件和已运行证据 | 混淆原型与主线 |
| Phase 1 重定定位和架构 | T02 A/C/D：确定边界、角色、固定主图 | 0 | 审查首版矩阵和取消、审批、修订语义 | 目标冲突 |
| Phase 2 规格与数据模型 | T03 A/E：Pydantic、规格版本、SQLite、API/TS 契约 | 1 | 旧版本冲突、非法 Schema、Windows 依赖探针 | 跨端漂移 |
| Phase 3 Planner | T05 C：模型适配、角色预设、规划校验修复 | 2 | V01 且用真实接口做一次结构化探针 | 模型坏 JSON |
| Phase 4 编排编辑器 | T04 B：保留已有画布，结构化规格、候选与确认 | 2，3 可用 fixture 替代 | V02 的草稿、替换与版本行为 | 旧草稿兼容 |
| Phase 5 真实执行 | T08 D/E/C：串行集成后加入 Send 并行、产物事务、消息和工具记录 | 2–4 | V03/V04 及串行网页闭环 | 汇聚重复或提前 |
| Phase 6 监控和人工交互 | T09 B/E，T10 D：执行视图、SSE、人工审批、取消 | 5 | V05/V06/V08 | 晚到事件 |
| Phase 7 验证与修订 | T11 C/D/B：Reviewer、机器校验、验证视图、一次批准后修订 | 5–6 | V07，保留原证据且终止有界 | 模型假通过 |
| Phase 8 本地交付与验收 | T12 F，T13 E：打包、性能测量、测试报告 | 7 | V01–V10，干净 Windows 与 REAL 报告 | 依赖安装、无 Key |

Phase 2 冻结契约后，B 可用同一 fixture 并行做 Phase 4，F 可并行编写验收场景。Phase 5 串行集成通过即可内部演示。并行、人工交互和一次修订全部通过后才签署首版。性能以基础环境和实测留档，P1 再扩大图规模。
